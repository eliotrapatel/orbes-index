## Gaps against §27

None: every §27 expectation that the platform contract also prescribes holds. (A GAP would be a place where §27 expects a different public state than the normative contract; none makes a forgery look authentic.)

Resolved since the previous report (orchestrator decisions, `PLATFORM-CONTRACTS.md` §2.4 / §2.5):

- **4a** — the signature is now verified before the genome-version support check: an edited genome version answers INVALID_SIGNATURE (as in the POC), not MALFORMED_CODE. Version 0 stays a reserved value refused by strict parsing (4h). A *validly signed* but unsupported genome version answers UNKNOWN (`UNSUPPORTED_GENOME_VERSION`, logged: the server is outdated).
- **9f** — SCAN_VELOCITY weighs 45 (was 35): with DEVICE_DIVERSITY (30) a same-place burst scores 62 ≥ 60 and is shown as SUSPICIOUS.
- **10l** — the revoked-key rule now runs before the registry: anything signed by a revoked key without a registry record older than the cut-off, registered identity or not, answers INVALID_SIGNATURE (`KEY_REVOKED`).

## What the system can and cannot detect

**Detected (forgeries are never AUTHENTIC*):**

- Any edit of the signed bytes — every single-bit flip of the 13-byte payload (versions, key id, identity, issue, day, nonce) and of the 64-byte signature, a whole identity rewritten to another registered product, a signature transplanted from another genuine code — whether submitted directly or printed as a new, perfectly decodable artifact (3, 4a, 5). Edits that strict parsing refuses (out-of-range or reserved fields) answer MALFORMED_CODE, every other edit — the genome version included — INVALID_SIGNATURE.
- Codes signed by any key ORBES does not hold: an unknown key id, the forger’s own key, 203 seeded random codes (100 raw, 100 with a well-formed payload, 3 more printed and photographed; 10a, 10b, 10g–10i).
- Codes signed with a **stolen** real key: UNKNOWN + CRITICAL `VALID_SIGNATURE_UNREGISTERED` for a new identity, SUSPICIOUS + CRITICAL `CODE_MISMATCH` for an existing product (registry nonce / payload-hash match). After revocation with a compromise time, codes recorded before it keep verifying; anything else the revoked key signed — later codes, new identities — answers INVALID_SIGNATURE; re-issue under the new key restores the product (10c–10p).
- Printed genome glyphs that disagree with the signed identity in ≥ 2 of ≥ 6 confidently read positions: SUSPICIOUS + `GENOME_MISMATCH` (4c).
- Revoked products, revoked and superseded codes (REVOKED + `POST_REVOCATION_SCAN`), with re-issue producing a new authentic artifact (7).
- A copied code once it is scanned in ways one object cannot be: two places farther than 500 km apart faster than 900 km/h (IMPOSSIBLE_TRAVEL, from city coordinates or, conservatively, country centroids minus country radii), more than 3 countries in 7 days (GEO_DISPERSION) — 2, 8, 9a–9c — or a burst of more than 20 scans in 60 min from more than 12 distinct sources in one place (SCAN_VELOCITY ⊕ DEVICE_DIVERSITY = 62; 9e–9h). Meanwhile the logged-in owner keeps OWNERSHIP VERIFIED with an unusual-activity notice (2f–2h), and the buyer of an unregistered piece shipped with a claim code still receives a registration token that only the claim code can use (9l–9m).
- Unreadable or malformed codes: no request at all when Reed-Solomon fails; any string up to 1024 characters is processed and recorded, and bad CRC, length, encoding (empty, non-base64url, more than 200 characters) or payload fields answer MALFORMED_CODE; only requests outside the schema (more than 1024 characters, a non-string code) get 400 and are not recorded (6).

**Not detected (by design or by limit):**

- **A single quiet copy.** A perfect copy of a genuine code (the bytes and the genome are public once photographed) verifies exactly like the original as long as its scans are plausible for one object: the first scan anywhere (2c, 8a), or two copies scanned in alternation more than 10.8 h apart between Paris and Tokyo (9 705 km at 900 km/h; 8f, 8h). A printed code proves that ORBES issued the identity, never that the object in hand is the original.
- **Short memory of one finding.** One IMPOSSIBLE_TRAVEL finding (weight 60) flags scans only while its linearly decayed weight still rounds to ≥ 60: with 30-day decay that is the next ≈ 6 hours (8f). The anomaly record stays OPEN for review.
- **Volume from one source.** The rules count distinct sources (IP pseudonym, else device cookie, else session), not cookies: many phones behind one address (a boutique wifi, a carrier NAT) count once, so a burst of copies scanned from one network is not shown — the price of not letting one client inflate the count by dropping its cookie (9j–9k).
- **Partial genome forgery.** One replaced glyph is tolerated as a misread (4d); a genome ring made illegible (sanded, smudged, fewer than 6 confident glyphs) is INCONCLUSIVE and never flags (4e). The genome check also depends on the client: a request without a genome reading is NOT_PROVIDED.
- **Who scans first.** While a product is unregistered, whoever scans any copy first is offered a registration token. The claim code shipped with the genuine piece is what stops the copy’s holder from registering (8g); products issued without a claim code have no such protection. Once the genuine buyer registers, every copy shows AUTHENTIC — REGISTERED (not to its holder) — the registration conflict is the visible signal (8j).
- **Rejected forgeries are not anomalies.** INVALID_SIGNATURE and MALFORMED_CODE scans are stored as scan / authentication events (visible under VERIFICATION EVENTS) but create no anomaly record, so a flood of invalid forgeries does not raise an alert by itself (3h).
- **Geo depends on the edge.** Location comes from proxy headers (GEO_MODE=headers here); without them (GEO_MODE=none) none of the travel or dispersion rules can fire.

## Method

- **Real stack.** Every scenario opens a fresh world: `createContext` (in-memory PGlite with all migrations, `MemoryKeyProvider`, every service) + `buildApp`, driven with `app.inject`. Products are issued, activated, revoked and re-issued, keys rotated and revoked through the **admin API** (an ADMIN session). Genuine artifacts are downloaded from `GET /api/admin/codes/:codeId/artifact.png` (30 mm, 600 dpi, ≈ 14 px per code unit). Forged artifacts are produced by the server's own render module (`renderArtifact`) from the forger's bytes and glyphs.
- **Phones.** Each device has its own cookie jar (`orbes_device` → device pseudonym), IP and location; the edge geo headers (GEO_MODE=headers, trusted proxy) carry city coordinates and the country, or the country only (9a–9c). Captures use the deterministic camera simulator (`test/support/camera-sim.ts`) with a preset per device cycling through typicalPhone, glare, tilted45, lowLight, worn, leather, small, clean (the `metal` preset is left out: 55 % in the scan matrix), a seeded random rotation, ±4° extra tilt and offset; a scan is a burst of up to 3 frames drifting 1.5°. Each frame goes through the scanner worker's decode step (`src/web/verify/frame-decoder.ts` → core decoder, genome reading on), and the request body is built by the scanner's own `buildVerifyInput` (`src/web/verify/capture.ts`).
- **Forger.** Byte-level attacks start from what a real scan of the genuine label read, edit it, and recompute the CRC-16 (it is public). Theft of the signing key is simulated by signing with the world's real private key outside issuance (`MemoryKeyProvider.sign`). Random codes come from a seeded PRNG (raw 79-byte strings; and frames whose payload parses as CODE-01/GENOME-01 naming the live key, by rejection sampling).
- **Time.** One manual clock per world, starting 2026-06-01 08:00 UTC and only moving forward; travel and decay scenarios set it explicitly (times in the tables are UTC). Anomaly thresholds are the production defaults (`DEFAULT_ANOMALY_CONFIG`) except in the second world of 9i.
- **Evidence.** Public state and body from the HTTP response; the internal reason list and genome check from `authentication_events` (to prove a state was reached for the claimed reason); anomalies from the admin API.

## Limitations

- The camera is simulated (perspective, lens, blur, noise, glare, occlusion, texture, JPEG) — no real phone, printer, ink spread or substrate. Decode robustness is measured separately in `docs/reports/scan-matrix.md`; here it only has to be good enough to carry the attacks.
- Frames are decoded whole (the upload path); the live scanner's canvas crop/scale step is browser-only and not exercised. The browser itself is covered by the Playwright E2E tests, not here.
- Scale is small: tens of devices per scenario, one product per attack. Rate limits are the test configuration (10 000/min): the hundreds of scripted submissions of scenarios 3, 5 and 10 come from one forger device and would hit the production limit (60 verify/min per IP) — a real forger would spread them over addresses; the phone scans stay far below it.
- Geolocation is taken at face value from the trusted-proxy headers; spoofed or VPN locations, and the IP-to-location accuracy of a real edge, are out of scope.
- PGlite runs one connection, so scans are serialised. `test/simulation/postgres.test.ts` runs scenarios 2, 8 and 10 on real PostgreSQL when `ORBES_TEST_POSTGRES_URL` is set (role with CREATEDB); this report was generated on PGlite.
- Key material and nonces are random per run, so artifacts differ between runs; states, anomaly types and counts are stable. Timings are wall-clock on the generating machine.
- Expectations are those of the §27 scenario list as briefed for this suite; where the platform contract says otherwise the check is a GAP, not silently re-aligned.
